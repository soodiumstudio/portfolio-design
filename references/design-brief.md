# AI에게 보낼 요청문 만드는 법

학생이 요청문을 쓰지 않아도 되게 만드는 파일이다.
1단계에서 번호 선택지로 받아 채운 화면 계획표(`screen-brief.md`)를
아래 틀에 옮겨 담으면 요청문이 된다.

계획표의 칸은 **학생이 쓴 게 아니라 내가 만든 보기 중 학생이 고른 것**이다.
그래서 빈 칸이 있을 수 없다. 빈 칸이 있으면 1단계에서 안 물어본 것이니 돌아가서 묻는다.

## 왜 이렇게까지 하나

`design` 스킬은 안 알려 주면 **자기가 알아서 정해 버린다.**
움직이는 화면인지 아닌지, 무슨 글꼴인지, 무슨 색인지, 화면을 몇 장 그릴지를 스스로 고른다.

그러면 두 가지가 망가진다.

1. 세 개의 생김새가 제각각이 되어 **비교가 안 된다.**
2. 학생이 **왜 그렇게 생겼는지 설명하지 못한다.**

아래 여섯 칸은 그 결정들을 **미리 정해서 잠가 두는** 칸이다.

## 요청문 틀

```
{프로젝트 이름} 포트폴리오용 화면입니다. 아래 조건을 그대로 지켜 주세요.

[1] 어떻게 만들지
움직이지 않는 그림 화면으로 만듭니다. 눌러지는 화면 아닙니다.
화면 크기는 {390 × 844 / 1440 × 900} 이고, 각 화면의 바탕을 그 크기로 고정합니다.

[2] 누구의 무슨 화면인지
- 쓰는 사람: {…에 익숙하고 …이 서툰 사람}
- 쓰는 순간: {한 손이다 / 서두른다 / 소리를 못 켠다}
- 이 화면에서 끝내는 일: {…}
- 사용자가 여기서 정해야 하는 것: {하나}
- 꼭 보여야 하는 것: 1) {…} 2) {…} 3) {…}

[3] 세 개가 똑같이 쓸 것 (여기는 절대 바꾸지 마세요)
- 글꼴: 제목 {…} / 본문 {…}  (구글 폰트로 불러오고, 대신 쓸 글꼴도 같이 적어 주세요)
- 색: 바탕 {…} / 글자 {…} / 강조색 {…} 하나만
- 간격: 8의 배수로 / 모서리 둥글기 {…}px / 손가락으로 누르는 것은 최소 44px
세 개 사이에서 다른 것은 **구조와 순서뿐**입니다. 글꼴과 색을 안마다 바꾸지 마세요.

[4] 만들 세 가지
- 안 A — {이름}: {사용자에게 시키는 일 한 줄}
  화면 순서: 1) {…} 2) {…} 3) {…}
- 안 B — {이름}: {…}
  화면 순서: 1) {…} 2) {…} 3) {…}
- 안 C — {이름}: {…}
  화면 순서: 1) {…} 2) {…} 3) {…}

[5] 화면 이름과 놓을 자리
아래 표 그대로 파일 이름과 위치를 정해서 canvas.json 을 만들어 주세요.

[6] 지켜 주세요
- 계획표에 없는 기능·화면·칸을 추가하지 마세요. 필요해 보이면 만들지 말고 먼저 물어보세요.
- 글은 실제 한국어로 써 주세요. "여기에 텍스트" 같은 건 쓰지 마세요.
- 모르는 값(금액·날짜·이름)은 지어내지 말고 [금액] 처럼 대괄호로 비워 두세요.
- 이모지를 아이콘으로 쓰지 마세요. 선으로 그린 아이콘을 써 주세요.
- 가짜 상태표시줄(9:41·배터리)과 가짜 자판을 그리지 마세요.
- 배경에 그라데이션을 깔지 마세요. 왼쪽에 색 띠를 두른 둥근 카드도 쓰지 마세요.
```

## [5] 화면 이름과 자리 — 그대로 쓰면 되는 표

`design` 스킬에는 규칙이 있다. 파일 이름은 **`이름.dc.html`** 이어야 하고,
이름이 서로 겹치면 안 되고, **하나는 반드시 `Main.dc.html`** 이어야 한다.
그래서 안 A의 첫 화면을 `Main`으로 둔다.
학생 눈에 보이는 이름은 `title`로 따로 준다 — 화면에는 "A · 1 홈"으로 보인다.

세로 화면(390 × 844) 기준. 가로 간격 470, 세로 간격 944.

| 파일 | 보이는 이름(title) | x | y |
|---|---|---|---|
| `Main.dc.html` | A · 1 {…} | 0 | 0 |
| `A2.dc.html` | A · 2 {…} | 470 | 0 |
| `A3.dc.html` | A · 3 {…} | 940 | 0 |
| `B1.dc.html` | B · 1 {…} | 0 | 944 |
| `B2.dc.html` | B · 2 {…} | 470 | 944 |
| `B3.dc.html` | B · 3 {…} | 940 | 944 |
| `C1.dc.html` | C · 1 {…} | 0 | 1888 |
| `C2.dc.html` | C · 2 {…} | 470 | 1888 |
| `C3.dc.html` | C · 3 {…} | 940 | 1888 |

모든 화면 `w: 390, h: 844`. 열었을 때 전체가 보이게 `launch`는 `{"view": "canvas"}`.

- 가로 화면(1440 × 900)이면 가로 간격 1520, 세로 간격 1000.
- 화면이 4장이면 가로로 하나 더 늘린다.
- **가로 한 줄 = 안 하나, 세로로 셋** 이 배치를 꼭 지킨다. 이래야 학생이 한눈에 비교한다.

각 줄 왼쪽에 쪽지를 붙이면 화면판만 봐도 설명이 된다.

```json
"annotations": [
  { "id": "axis-a", "x": -300, "y": 0,    "w": 240, "text": "안 A — 다 보여 주고 고르게 한다" },
  { "id": "axis-b", "x": -300, "y": 944,  "w": 240, "text": "안 B — 제일 나은 하나만" },
  { "id": "axis-c", "x": -300, "y": 1888, "w": 240, "text": "안 C — 한 번에 하나씩" }
]
```

## 보내기 전에 확인

- [ ] [2]의 "정해야 하는 것"이 한 줄로 채워졌는가 (비었으면 1단계로 돌아간다)
- [ ] [3]의 글꼴과 색이 **하나씩만** 적혀 있는가 (안마다 다르게 적었으면 잘못이다)
- [ ] [4]의 셋이 "사용자에게 시키는 일"로 구별되는가 (색·배치 차이면 다시 정한다)
- [ ] 학생에게 이 요청문을 보여 주었는가

## 받은 다음 확인

- [ ] 화면이 9장(또는 계획한 수)인가
- [ ] 세 개의 글꼴과 색이 진짜로 같은가
- [ ] "꼭 보여야 하는 것" 3개가 세 개 모두에 있는가
- [ ] 지어낸 숫자가 없는가 (대괄호로 비워 뒀는가)

하나라도 아니면 `revise.md`의 문장 틀로 고쳐 달라고 한다.
**학생에게 넘기기 전에 이건 내가 잡는다.**
