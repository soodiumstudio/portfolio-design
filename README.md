# portfolio-design

**AI에게 화면 세 개를 받아서, 고치고, 하나 고르기**

빈 화면에서 시작하지 않습니다.
어떤 화면이 필요한지 먼저 정리하고 → 푸는 방법이 다른 세 개를 AI에게 받고 →
학생이 직접 고치고 → 기준을 세워 하나를 고르고 → 무엇을 버렸는지까지 남깁니다.

**학생이 치는 건 "화면 만들어줘" 한마디입니다.**
필요한 정보는 스킬이 `AskUserQuestion`으로 되물어서 채웁니다.
학생은 **보기를 누르기만** 하고, 보기에 없는 답은 직접 쓰는 칸에 씁니다.
`잘 모르겠어요`를 눌러도 멈추지 않습니다 — 스킬이 정하고 이유를 알려 주고 넘어갑니다.

**학생이 md 파일을 열 일은 없습니다.** 계획표도 기록장도 스킬이 쓰고, 내용은 대화창에 보여 줍니다.

**말 잘하는 학생과 못하는 학생의 결과물이 갈리지 않게 하는 것**이 이 스킬의 설계 목표입니다.

## 설치

터미널에 아래 한 줄을 입력하세요.

```bash
git clone https://github.com/soodiumstudio/portfolio-design.git ~/.claude/skills/portfolio-design
```

Claude Code를 껐다 켜면 바로 쓸 수 있습니다.

> ⚠️ `/plugin install` 은 쓰지 않습니다. 환경에 따라 `/plugin` 자체가 없습니다.
> 스킬은 `~/.claude/skills/` 에 폴더로 넣으면 그대로 인식됩니다.

## 업데이트

```bash
cd ~/.claude/skills/portfolio-design && git pull
```

## 사용

Claude Code 입력창에 (터미널 아님):

    /portfolio-design

그리고 **"화면 만들어줘"** 라고 하면 됩니다.
폴더를 보고 지난번에 어디까지 했는지 알아서 이어 갑니다.
준비물은 없습니다. 문제 정의서가 있으면 붙여넣으면 더 좋습니다.

학생이 기억할 건 세 가지뿐입니다.

```
① 명령 치고 "화면 만들어줘"
② 보기가 뜨면 누르기. 모르면 '잘 모르겠어요'
③ 고칠 때는 느낌 말고 '본 것'을 말하기
```

학생이 타자를 치는 건 ①과 ③뿐입니다.

### 준비 확인은 스킬이 합니다

실행하면 **화면 그리는 도구(node)와 폴더 위치를 스킬이 직접 확인**합니다.
다 되어 있으면 아무 말 없이 시작하고, **걸린 것만** 보여 주고 멈춥니다.
학생이 "완료"라고 하면 **다시 확인하고** 넘어갑니다 — 말만 믿지 않습니다.

도구가 없어도 수업은 됩니다. 글과 손그림으로 진행하고 계획표는 그대로 남으니,
나중에 그림만 다시 받으면 됩니다.

## 설계 원칙

- **되묻는다. 시키지 않는다** — 필요한 건 전부 `AskUserQuestion`으로 물어서 채웁니다. 주관식으로 묻지 않습니다.
- **확인할 수 있는 건 묻지 않는다** — "○○ 하셨나요?" 대신 스킬이 직접 돌려 봅니다. 학생에게 묻는 건 스킬이 못 고치는 것뿐입니다.
- **`잘 모르겠어요`에서 멈추지 않는다** — 스킬이 정하고 이유를 말하고 넘어갑니다. 단 비교 기준과 마지막 선택만은 학생이 합니다.
- **학생에게 파일을 열게 하지 않는다** — 파일은 스킬이 쓰고, 내용은 대화창에 보여 줍니다.
- **요청문은 스킬이 쓰고, 학생에게 보여 준다** — 프롬프트 실력을 평가하지 않습니다. 대신 무엇을 시켰는지는 알게 합니다.
- **세 개의 글꼴·색·간격은 똑같이 고정한다** — 다른 것은 구조와 순서뿐이어야 비교가 성립합니다.
- **받은 화면은 결과물이 아니라 반응할 거리다** — 최소 두 바퀴 고치게 하고, 한 바퀴마다 한 줄씩 이유를 남깁니다.
- **UX를 배운 적 없는 학생을 기준으로 말한다** — 전문 용어를 쓰지 않습니다. 스킬 안에 바꿔 쓸 말 표가 있습니다.
- **고르는 건 학생이다** — AI가 대신 고르면 "왜 이렇게 했어요?"에 답할 수 없습니다. (채점표 −3점)
