# Part A — 3회차: 안 A·B·C 만들기

## A-1. 화면 요구 명세 (실습의 본체)

`/design` 을 바로 부르지 않는다. 명세 없이 만든 화면은 예쁘지만 문제와 무관하고, 루브릭 D-7(문제와 솔루션 1:1)에서 최대 1점이 된다.

문제 정의서에서 초안을 만들어 보여 주고 학생이 고치게 한다. `03_design/screen-brief.md`:

```markdown
# 화면 요구 명세
## 이 화면이 끝내주는 과업
{사용자가 무엇을 끝내려고 이 화면에 오는가}
## 사용자가 여기서 내려야 하는 결정
{하나로 적는다. 두 개 이상이면 화면을 나눠야 한다는 신호}
## 반드시 보여야 하는 정보
1. 2. 3.
## 진입 경로 / 완료 조건
## 플로우 (3~5단계)
1단계 {화면} → 여기서 내리는 결정 → 다음으로 가는 트리거
2단계 …
```

**플로우를 여기서 확정한다.** 5회차 휴리스틱 평가가 이 파일을 그대로 입력으로 쓴다.

## A-2. 안을 3개 만든다

하나를 잘 만드는 게 아니라 **접근이 다른 3개**를 만든다. 안이 하나면 4회차에 비교할 게 없고, 루브릭 최핵심 항목(D-6, B-4)이 통째로 0점이 된다.

먼저 학생과 **접근 축**을 정한다. 예:
- 안 A: 정보를 다 보여 주고 사용자가 고른다 (통제 우선)
- 안 B: 추천 하나만 보여 준다 (결정 부담 최소)
- 안 C: 단계를 쪼개 하나씩 묻는다 (실패 가능성 최소)

축이 정해지면 `design` 스킬을 호출해 아트보드를 만든다. 프롬프트에는 명세의 과업·결정·필수 정보를 그대로 넣는다.

## A-3. 저장 (5회차 입력이 된다)

각 안의 화면을 PNG로 내보내 **반드시** 저장한다.
```
03_design/options/A/01.png, 02.png …
03_design/options/B/…
03_design/options/C/…
03_design/options/notes.md   ← 각 안이 어떤 접근인지 한 줄씩
```
학생이 내보내는 법을 모르면 알려 준다. 이 파일이 없으면 5회차를 할 수 없다.

## A-4. 자가 점검
- [ ] 세 안이 "색이 다른" 수준이 아니라 **접근이 다른가요**?
- [ ] 각 안이 명세의 '내려야 하는 결정'을 다르게 처리하나요?
- [ ] PNG가 `03_design/options/` 에 저장됐나요?

# Part B — 4회차: 비교하고 고르기 ★

루브릭이 유일하게 ★를 붙인 항목이다. D-6(4점) + B-4(3점) + 속성 스크리닝 Q7. 여기서 상위권이 갈린다.

## B-1. 비교 기준을 학생이 정한다

3개를 고르게 한다. AI가 제안하지 않는다. 기준은 **문제 정의서의 성공 지표에서 나와야 한다.**
> "성공 지표가 '저녁을 거르지 않는 날 수'였죠. 그럼 어떤 기준으로 안을 비교해야 할까요?"

## B-2. 채점

| 기준 | 가중 | 안 A | 안 B | 안 C |
|---|---|---|---|---|

각 칸에 점수만 쓰지 말고 **왜 그 점수인지 한 줄**을 붙인다. 근거 없는 표는 면접에서 무너진다.

## B-3. 선택과 트레이드오프 — 이 스킬의 결승점

`03_design/tradeoff.md` 를 루브릭 피드백 뱅크가 지정한 **4블록** 형식으로 만든다. 그대로 포트폴리오 한 페이지가 된다.

```markdown
# 왜 이 안을 골랐는가
## 1. 안 A·B·C          {각 안 썸네일 + 한 줄 설명}
## 2. 비교 기준          {기준 3개와 그 기준을 고른 이유}
## 3. 선택과 이유        {고른 안 + 근거}
## 4. 포기한 것과 보완    ← 여기가 만점을 가른다
- 포기한 것: {구체적으로}
- 그 손해가 사용자에게 미치는 영향: {한 문장}
- 어떻게 보완했는가: {구체적 설계}
```

**4번이 비어 있으면 이 단계는 끝나지 않았다.** "포기한 게 없다"고 하면 다시 묻는다:
> 안 B를 골랐다는 건 안 A가 잘하던 무언가를 버렸다는 뜻입니다. 안 A만 할 수 있었던 게 뭐였죠?

## B-4. 마무리
- `decisions.md`에 기록: 비교 기준 / 고른 안 / 포기한 것 / 보완
- 자가 점검:
  - [ ] '포기한 것'이 구체적으로 적혀 있나요? ("없음"은 오답입니다)
  - [ ] 비교 기준이 성공 지표에서 나왔나요?
  - [ ] 이 페이지만 보고 왜 그 안인지 남이 이해할 수 있나요?

## 공통 규칙 (이 스킬에도 그대로 적용)

1. **입력 게이트** — 필요한 정보가 없으면 질문부터 한다. 추측해서 진행하지 않는다.
2. **근거 강제** — 모든 주장에 근거를 붙인다. 리서치는 출처 URL, 평가는 화면 위치, 채점은 원문 인용.
3. **불확실 분리** — 확인 못 한 것은 결과물 맨 뒤 `## 확인 필요` 에 따로 모은다. 본문에 섞지 않는다.
4. **분량 상한** — 발견 항목은 Top 5, 액션은 3개까지.
5. **학생이 결정한다** — AI는 선택지를 좁혀 주고, 고르는 것은 학생이다. AI가 대신 고르면 채점표 F-3(AI 결과물을 설명할 수 없음, -3점)에 그대로 걸린다.
6. **판단 기록** — 학생이 무언가를 고를 때마다 `decisions.md` 에 한 항목을 추가한다.

## 작업 폴더

산출물은 프로젝트 폴더 아래에 쌓인다. 없으면 프로젝트 이름을 묻고 만든다.

```
PORTFOLIO/{프로젝트명}/
  01_research/  02_problem/  03_design/  04_heuristic/  05_review/
  decisions.md  progress.md
```

처음 만들 때 학생에게 알린다: "앞으로 매주 이 폴더에 결과가 쌓입니다. **항상 같은 폴더를 열어야** 이어집니다."

`decisions.md` 기록 형식:
```
## [N회차] {무엇을 골랐는가}
- AI가 제안한 것: {…}
- 내가 고른 것: {…}
- 이유: {한 문장}
- 포기한 것: {있으면}
```

## 끝낼 때

1. 산출 파일을 해당 폴더에 저장한다.
2. `decisions.md` 와 `progress.md` 를 갱신한다.
3. 아래 자가 점검을 출력한다.
4. 다음 단계 명령을 한 줄로 안내한다.
